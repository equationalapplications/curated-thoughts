## 3. Design v10

1. **Stage 1 (closed-set chunk search, NEW SQL):** unchanged from v9 — fact-bearing-doc-restricted top-k (hash hop ∪ proposal chain, live gate-eligible filter, `documents.hash` dedupe with deterministic row choice); rule (i) searches 261 chunks, rule (ii) searches 62 hash-hop-hit chunks with chunk-level membership; skip-aware; raw embed; k swept with floor (start 8).

3. **Decision rules:** (i) restricted-set fact-cosine floor; (ii) chunk-score floor with chunk-level membership.
4. **Floor-missing semantics — ONE rule (r9 M1):** when the two-stage floor for (model, scheme) is missing but the v1 floor exists, the call **falls back to v1** (v1 embed, v1 floors, v1 label — can open). When BOTH are missing: v1's uncalibrated behavior (gate `uncalibrated`, no entries). **Embed-skip rule follows: skip the embed only if BOTH keys are missing** (dual-key rule restated accordingly). Guard failure (absent/mismatch/mixed) ⇒ v1 fallback as before. Below-floor stage 1 ⇒ closed (no fallback).
5. **Two-stage active/off + labels:** as v8/v9 (default-on flip OR `--two-stage`; `CURATED_WISDOM_SINGLE_STAGE=1` + `--single-stage` off-switch; `semantic-v2-two-stage:{key}` stdout label when active; pinned stderr line untouched).
6. **Model guard completion — pass-id snapshot + `ct_reindex_pass_docs(pass_id, doc_id, embed_key)`** (+ migration, **ungated idempotent DDL following the V23/V26 pattern**, r9 m2); snapshotted doc not indexed-under-new-key (incl. superseded-job `pending`) blocks completion; file-missing counted `model_guard_skipped_docs`. **Purge completeness (r9 m2): the clear transaction additionally deletes the guard/pass/stamp meta keys, the breaker baseline/state keys, and all `ct_reindex_pass_docs` rows.**
7. **Floors + acceptance:** as v9; letter [PROPOSED — Kurt pins]: hit@2 both arms, two-stage ≥ 0.30 AND ≥ single-stage, FP ≤ 0.05, same paired run; live `model_guard=ok` recorded.
8. **Destructive-pass safety (r9 M2–M4 + m1/m3/m4 — scope corrected):**
   - **Diff-swap scope narrowed (r9 M2):** the diff-swap guarantees lossless handling ONLY where hashes are unchanged (force-rechunk under the same chunker, model swaps — re-embed in place). **Position-shifting edits and chunker-version bumps rehash downstream chunks; those chunks are deleted+reinserted, cascading `curated_relationships` and orphaning chunk_id-only evidence — this is a PRE-EXISTING behavior of today's full swap, now explicit in §4;** a text-match remap (keep chunk_id, UPDATE position/content_hash, record old→new hash remap for evidence) is listed as follow-up work with a mid-document-insertion test in the spec's test list. Embed-then-swap ordering retained for the changed-chunk set: read/chunk/embed OUTSIDE any transaction, then ONE short immediate transaction (upsert + delete-removed + insert-new + mark indexed; `upsert_document` writes inside it) — no write lock across the network call (5s busy timeout).
   - **Diff-swap mechanics (r9 m4):** empty-hash rows are treated as REMOVED (partial index can't match them); re-embed-in-place is an UPDATE of `embeddings` (or delete+insert in the same transaction) — never a bare INSERT (no unique constraint on chunk_id; duplicates would double-return in `semantic_search`).

Threshold **max(⌈0.05·L⌉, 10)** with L = heal's own selection; **regrade's breaker uses its OWN denominator = live `librarian_evidence` rows** (r9 m1).
   - **Regrade scope corrected (r9 m1):** the in-migrate path is dead on V20+ brains; the breaker covers the manual `ct evidence regrade` command (and pre-V20 replicas via `skipped_destructive=true`, accepting the stated V21+ hold as the safe direction). Regrade's hard-delete threshold denominator defined on its own population.
